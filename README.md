# Grok Bot 多岗流水线

我的判断是：Agent Wallet 会带起一轮新叙事。历史不会重演，但会押着同样的韵脚。这一次的韵脚是：人做过的事，可能会用 Agent 再做一遍。

Agent 时代，人的注意力肯定不够用，必须用上 AI。所以我在试着建一套流程。这个时代，AI First。

叙事还在形成，我选择先下场，把参与做成一条能自己跑的流程。

这条流程用来自动捕捉 alpha。发现把窗口送进来，研究只给三种结论，执行在授权范围内推进，每个账户分开算。人留在该签字的地方。

这是我目前个人在用的工作流，整理出来供参考。仓库只放方法和空模板。账户、密钥、会话、真实地址和关注名单都留在使用者自己的机器上。数字、账户、信息源，换成你的。

## 背景

Alpha 的窗口通常短于一个人的注意力。公开线索、新出现的机会、资格、费用、已经拿着的仓位，再加上多个账户各自的余额，如果都堆进同一个对话，人会漏，Bot 也会越权。

我把它拆成一条流水线，自己先用：

- **一套策略。** 发现和研究共用同一套准入标准。
- **按账户执行。** 有几个账户就建几只只读账户岗。资格、余额、仓位分开算，不写死账户个数。
- **执行是唯一执刀。** 步骤包写明这次参与的是哪一个、哪几个，或全部有资格的账户。
- **拍板只走 1:1。** 管家把需要人决定的事转到与主人的一对一。协作群只收通知和回执。
- **真相在磁盘上。** 工程记忆写在 `SAVENOW`。换一个对话，不自动变成一次新的授权。

「自动捕捉」指的是这条流水线按岗位往下走。研究结论是可参与，执行才推进。否决和超限回到管家，再由人确认。持仓岗只看已经拿着的，旧仓位不会被重新当成新机会。

仅供参考。这是个人探索出来、目前在用的流程。你拿到的是结构。授权额度、参与哪些账户、什么叫一个合格窗口，都由你自己写进 `MEMORY.md`。

## 架构

用浏览器打开 [`docs/architecture.html`](docs/architecture.html)。这是单文件，克隆到本机后直接打开。GitHub 网页上只会显示源码。

建议按这个顺序读：

1. 主路径从左往右，再向下：主人 → 管家 → 发现 → 研究 → 执行。
2. 研究只有「可参与」才把事情交给执行。否决从研究上方回到管家，超限从执行下方回到管家，再由管家找主人做 1:1 确认。
3. 账户岗按实际账户数复制。每只只读自己的账户，不收私钥、不代签。
4. 协作群只收通知和回执。需要人拍板的事不在群里问。
5. 工程记忆是磁盘上的 `SAVENOW`。聊天记录不能代替它。

岗位说明、授权表和落地清单在 [`docs/handoff.md`](docs/handoff.md)。

## 角色

| 角色 | 干什么 | 硬边界 |
|---|---|---|
| 主人 | 书面裁定，人侧签名 | 私钥留在人这边 |
| 管家 | 编排、验收、把人门事项转到 1:1，维护记忆入口 | 不代签，不收私钥 |
| 发现 | 按信息源捞候选，把来源和时间一起交出去 | 不连钱包，不下单 |
| 研究 | 三态裁决：可参与 / 暂不参与 / 信息不足 | 不下单，不代签 |
| 执行 | 把「可参与」写成步骤包并推进 | 唯一执刀；超限上交，不喊整组停 |
| 账户岗 × N | 每个账户一只。余额、资格、限额只读，复核本账户步骤包 | 不收私钥，不代签，不碰其他账户的会话 |
| 持仓 | 看已持仓能不能卖，给出建议 | 不自己执行，不把持仓异动当成新机会 |
| 协作群 | 跨岗通知和回执 | 不是拍板的地方 |
| 工程记忆 | `SAVENOW.md` 和 `_savenow/` | 不存放密钥 |

发现按信息源拆入口。社交公开线索和新盘只是样例，可以换成你的信息源。个人关注名单不在这个公开版本里。

## 怎么开始

1. 读完 [`docs/handoff.md`](docs/handoff.md)。
2. 把 `template/` 复制到你自己的工程根目录，再改 `PROJECT.md`、`ROLES.md`、`MEMORY.md`。
3. 交接稿第 0 节只贴给你**新建**的 Bot。整段丢进已经有 Bot 的群，会被当成开工指令。
4. 授权表里的 `N` 是空着等你填的样例。写成你自己的数字之后，执行岗才按那个阈值推进。
5. 会话路径、账户和密钥用你自己的。

最小可跑是 4 个 Bot：管家、发现、研究、执行兼一只账户的只读。账户数量之后再加，加一只就复制一只账户岗。持仓和更多发现入口，等这条线稳定后再拆。

## 留在你自己机器上的东西

- 私钥、助记词、API 密钥、会话目录、真实钱包地址、服务器密码
- 关注名单和认可账号
- 已经确认的单、历史成交
- 口头说过、但没写进 `MEMORY.md` 的临时授权
