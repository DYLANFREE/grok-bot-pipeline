# Grok Bot 多岗流水线 · 可复用架构交接（分享版）

- 写出时间：2026-10-28 12:47 Asia/Hong_Kong
- 用途：把「管家 + 专岗流水线 + 工程记忆」整套模式交给另一台 Grok Bot 照着建
- 边界：**不含**私钥 / 助记词 / API 密钥 / 会话目录 / 真实钱包地址 / 服务器密码；对方必须换成自己的账户与密钥
- 分享说明：这是给人看的参考骨架。第 0 节只贴给朋友**自己新建**的 Bot。不要整段丢进已经有 Bot 的群里当指令。关注名单不在本版。
- 本版以「一套策略、两只执行」的交易/机会流水线为样板；其它业务线可按同一骨架裁剪

---

## 0. 给对方 Bot 的开场指令（可整段粘贴）

请按本文件从零搭一套「管家编排 + 专岗流水线」。先读完全文，再按第 7 节清单落地。禁止向人要私钥或助记词；花钱与外发必须有明确授权规则；聊天不是恢复前提——工程真相写在磁盘上的 `SAVENOW.md` 体系里。

---

## 1. 总原则（必须先立住）

1. **工程承载记忆，不是某个 Bot 的私聊。** 换对话、换模型、换协作者，只要打开工程根就能恢复。
2. **事实 / 推理 / 未知 / 主人裁定 / 执行授权 / 完成证明** 分开写；旧授权不继承。
3. **一个管家 Bot** = 编排、验收、人门推到与主人的 1:1；不绕过专岗硬规则；不代签；不收私钥。
4. **专岗 Bot** 只干自己那一段；跨工程不自建第二套「当前真相」。
5. **群聊是协作房间**，不是埋主人确认的地方；需要人拍板的事项由管家转到 1:1。
6. **群满员时**：溢出岗位不进群，产出经管家编排转发。

## 2. 推荐组织形态

### 2.1 角色骨架

```
发现（可多条入口） → 研究评估 → 执行（步骤包）
                              ↘ 账户1（只读资格 + 复核）
                              ↘ 账户2（只读资格 + 复核）
持仓哨兵：已持仓涨跌 / 可卖性 / 建议卖出线索（不自执行）
管家：编排 / 验收 / 人门 1:1 / 工程记忆维护
群「流水线协作」：跨岗通知与回执
```

### 2.2 「一套策略、两只执行」

| 层 | 含义 |
|---|---|
| 一套策略 | 发现与研究共用同一套准入逻辑与风险语言 |
| 两只执行 | 两个钱包/账户的资格、余额、仓位**分开算** |
| 空投 / 专属盘 | 默认可双份（各账户各自有资格才算一份） |
| 交易 | 可双开或偏仓到一只；步骤包必须标明 **账户1 / 账户2 / 双开** |

只有一个账户时：先建「发现 → 研究 → 执行 + 账户1」，账户2 以后再加，不要把单账户写成双开。

### 2.3 发现入口拆分（示例）

按**信息源**拆岗，避免一个岗又扫社交又扫发币台：

| 岗 | 盯什么 | 不做什么 |
|---|---|---|
| 发现｜社交/X | 官方与可交叉验证大号的线索 | 不主评市值/热度；不连钱包 |
| 发现｜新盘/台上 | 指定叙事台子上的新盘与节奏 | 不追泛 meme；不催平台币本身 |

产出统一汇到 **研究评估**。已持仓项目的异动标「持仓异动」，交持仓 + 研究，**不当新机会重交**。

## 3. 各岗一页纸（粘贴进 Bot 说明时用）

每个专岗 profile / 系统说明建议固定四段：**我是谁 · 干什么 · 目标 · 硬边界**。

### 管家
- **是谁**：编排与验收员，不是交易员。
- **干什么**：拆任务、对岗、收齐证据、人门事项推主人 1:1、维护工程记忆入口。
- **目标**：流水线接得上；未知项有人推进；主人只审该审的。
- **硬边界**：不代签；不收私钥；不以「群安静」当「一切正常」；不以「文件在」当「程序在跑」。

### 发现岗
- **是谁**：线索哨兵。
- **干什么**：按入口捞候选；安全筛选（来源粉量/认证/年龄；要私钥或无限授权 → 丢弃或高风险）；可看/谨慎时 @研究。
- **目标**：不错过可验证窗口；不把钓鱼推进下游。
- **硬边界**：不连钱包、不下单、不碰私钥。

### 研究评估
- **是谁**：能不能参与的裁判（建议用更高智能档）。
- **干什么**：查链、资格、费用、官方规则、钓鱼面；结论只要三种：**可参与 / 暂不参与 / 信息不足** + 证据链接；可参与则写仓位上限与账户1/2/双开资格。
- **可交易标的**：下结论前尽量跑合约安全审计 + 池深/持仓集中度 + 公开讨论热度，整理成短简报（亮点 / 链上数据 / 安全评级）。
- **铸造分型**（若做铸造）：放行时标明 **纯凭证 / 可卖 NFT / 可卖代币**；可卖型补二级信息；deny 续作时写「持有观察要点」给持仓岗。
- **硬边界**：不下单、不代签。

### 账户岗（每账户一只 Bot）
- **是谁**：该账户的只读管理员。
- **干什么**：余额/限额/策略/资格只读；步骤包标本账户时复核；资金异动报群。
- **硬边界**：不收私钥；不代签；不碰另一账户的会话目录；连接用官方配对流程，不是「贴地址」。

### 执行岗
- **是谁**：步骤包作者与唯一执刀推进员。
- **干什么**：把「可参与」落成链 / 代币 / 金额 / 调用；标签账户；在授权规则内推进或挂草稿等人。
- **硬边界**：不代签；NeedConfirmation 如实告知；单项等人时**不喊整组停**；铸造/卖出推进前核链上余额，已满额则 skip。

### 持仓岗
- **是谁**：持仓哨兵。
- **干什么**：汇总已持仓涨跌；判断能不能卖、怎么卖；维护「可卖观察清单」；建议卖出 → 研究复核 → 执行挂卖出包。
- **硬边界**：**不自 execute**；不扫全新盘当发现。

## 4. 授权速查表（按风险改数字）

把下表写进管家与执行岗说明；数字按主人风险偏好改：

| 情形 | 谁推进 |
|---|---|
| 研究通过 + 单笔 ≤ N（样例 N=4 USDT） | 执行可推进（App 签名弹窗仍可能出现） |
| > N / 未知合约 / 否决 / 信息不足 | 须主人书面确认（管家 1:1） |
| App 人门（领域名、扫码等） | **单项**等人；其它工作线继续 |
| 主人已确认的铸造/买入/卖出 | **仅执行岗**执刀；账户岗只读复核 |
| 推进前链上余额已 ≥ 授权数量 | skip，报管家，勿重复做 |
| 私钥 / 助记词 | **永不**接收 |

建议把每条定成带编号的决定（如 `D-YYYYMMDD-001`），写进工程 `MEMORY.md`，避免口头规矩漂移。

样例决定语言（可改写）：
- **D-001**：单项人门不喊整组停。
- **D-002**：研究通过且 ≤N 可推进，不必每笔再问。
- **D-003**：一套策略、两只执行（资格与仓位分开）。
- **D-004**：铸造/买卖唯一执刀 = 执行岗。

## 5. 工程记忆（Savenow）——对方必须自建的目录

在工程根（示例 `projects/<你的流水线名>/`）放：

```
SAVENOW.md                 # 唯一恢复入口与阅读顺序
_savenow/
  GUIDE.md                 # 怎么恢复 / 保存 / 交接
  PROJECT.md               # 长期目标与边界
  ROLES.md                 # 岗位单一当前真相（与 Bot profile 对齐）
  CHECKPOINT.md            # 当前断点与下一道门
  MEMORY.md                # 长期决定与教训（含 D-编号）
  CHANGELOG.md             # 最近重要变化
  INDEX.md                 # 索引
  handoffs/                # 需要证据的工作线交接
  history/                 # 已压缩但仍可追溯的记录
  inputs/                  # 名单、观察清单、准入等（非密钥）
```

根目录再放 `AGENTS.md` / `CLAUDE.md`：只指路到 `SAVENOW.md`，**不复制当前状态**。

全机若有多条工程，另建：

```
projects/_meta/
  INDEX.md                 # 全机导航
  ORG.md                   # 岗位总表（一页看清谁干什么）
```

**恢复顺序（专岗与管家都遵守）**：`SAVENOW.md` → `GUIDE` → `PROJECT` → `ROLES` → `CHECKPOINT` → `INDEX` → 只加载当前问题相关的 handoff / MEMORY。没有当前请求时：说明恢复到哪，然后等待——旧待办不是新授权。

**保存规则**：只有主人明确说「保存现在 / savenow」同类话时才写入记忆体系；保存≠改业务、≠部署、≠下单。

## 6. 协作与例程

### 6.1 群
- 建一个流水线群；成员 = 必须实时对线的岗（通常：发现主入口、研究、执行、账户1、账户2）。
- 溢出岗（持仓、新盘……）群满则不进，由管家代转。
- @点名要做事的岗；「记一下 / 无需交易包」这类信息性事项写清，避免误开步骤包。

### 6.2 例程（按需）
| 例程 | 建议节奏 | 产出 |
|---|---|---|
| 社交线索巡检 | 每 3 小时营业时段 | 可看清单；无新则安静或只记笔记 |
| 新盘巡检 | 整点或固定窗 | 仅叙事台内候选；空窗可不催主人 |
| 持仓巡检 | 每天 1～2 次 | 涨跌 + 可卖性；实质变化才推 1:1 |
| paper/程序保活 | 每几分钟 | 健康则**不要刷屏**主人 |

空窗、连续健康：**默认不向主人汇报**。

### 6.3 文件权限提醒（若有共享程序读 inputs）
非密钥输入发布后应可被只读程序打开（样例 `0644`）；用专用发布脚本原子写入。禁止把钱包会话目录 chmod 开放。

## 9. 明确不要复用的东西

- 任何真实地址、会话目录、API Key、服务器登录、助记词。
- 别人的「已确认单」与历史成交（防重复执行）。
- 口头说过但未写入 MEMORY 的临时授权。
- 把 paper/观察程序误当成实盘权限。
- 别人的关注名单、认可账号、社交巡检对象。

## 10. 最小可跑版本（若对方人手少）

只要 4 个 Bot 也能转起来：

1. 管家  
2. 发现（合并社交+台上，但心里仍按入口过滤）  
3. 研究  
4. 执行兼账户只读（单账户）

持仓与第二条账户等稳定后再拆。宁可岗少而边界清，不要一人身兼发现+研究+执行还无授权表。

---

## 11. 验收标准（给管家用）

- 新会话能从 `SAVENOW.md` 恢复到正确断点。  
- 发现产出带来源与时间，研究结论只有三态之一且带证据。  
- 步骤包必有账户标签；超限必进 1:1。  
- 重复推进会被余额/回执检查挡下。  
- 空窗与健康检查不打扰主人。
